# Задание 1 — автоматизация бенчмарка Wukong

Консольная программа на **C# / .NET 10** выполняет два прохода Black Myth: Wukong Benchmark Tool из Steam: с настройками для CPU и GPU. Сохраняет характеристики компьютера, настройки и показатели FPS в HTML- и JSON-отчёты, затем восстанавливает исходные настройки.

**Статус:** сборка, 33 теста и демонстрационный сценарий проверены на macOS. Работа со Steam, меню, настройками и настоящими результатами бенчмарка на Windows не проверена. Реальных замеров FPS нет.

## Запуск на Windows

Нужны Windows x64, Steam с выполненным входом и установленный **Black Myth: Wukong Benchmark Tool** (App ID `3132990`). Сначала запустите бенчмарк вручную для первоначальной настройки и подготовки шейдеров, затем закройте. Во время автоматического запуска оставьте рабочий стол разблокированным и окно бенчмарка на переднем плане.

Распакуйте готовую сборку вместе с папкой `config` и выполните:

```powershell
.\WukongRunner.exe run
```

Для готовой сборки установка .NET не требуется. Для запуска из исходников установите **.NET SDK 10.0.401** и выполните из папки `task-1`:

```powershell
dotnet run --project src/WukongRunner.Cli -c Release -- run
```

Настройки меню находятся в [config/automation.json](config/automation.json). По умолчанию программа ждёт 30 секунд и нажимает Enter. **Эта последовательность требует проверки на Windows**; при отличиях меню её нужно скорректировать. Завершение прохода определяется по свежему, полностью записанному и корректному файлу результата.

## Выбор настроек

| Параметр | CPU-проход | GPU-проход |
| --- | --- | --- |
| Разрешение | 1280 × 720 | Разрешение основного рабочего стола |
| Масштаб рендеринга | 50% | 100% |
| Качество графики | Низкое | Кинематографическое |

Низкое разрешение и качество уменьшают влияние видеокарты в CPU-проходе. Полный масштаб и высокое качество увеличивают нагрузку на GPU. В обоих проходах отключены VSync, лимит FPS и генерация кадров, чтобы не ограничивать и не завышать результат. Трассировка лучей отключена для совместимости, используется оконный режим.

Профили задают предполагаемую нагрузку: без реальных измерений нельзя подтвердить, что производительность ограничена именно CPU или GPU. Параметры и дополнительные пути описаны в [инструкции по конфигурации](config/README.md).

## Результаты и восстановление

В `results/` создаётся отдельная папка запуска: `report.html`, `report.json`, исходные результаты, применяемые конфигурации, резервная копия настроек и `run.log`. Отчёт содержит CPU, GPU, RAM, средний/минимальный/максимальный FPS и статус проверки настроек.

При ошибке или Ctrl+C программа пытается восстановить настройки. После принудительного завершения закройте бенчмарк и укажите сохранённый файл восстановления:

```powershell
.\WukongRunner.exe recover --manifest ".\results\папка-запуска\recovery.json"
```

## Проверка на Mac и сборка

С установленным .NET SDK выполните из `task-1`:

```sh
dotnet build WukongRunner.sln -c Release
dotnet test --project tests/WukongRunner.Core.Tests/WukongRunner.Core.Tests.csproj -c Release
dotnet run --project src/WukongRunner.Cli -c Release -- demo
```

Демонстрация использует **вымышленные данные**, не запускает Steam и не измеряет производительность Mac. Подробности: [проверки](docs/validation.md), [ограничения интеграции](docs/integration-notes.md).

Сборка для Windows из macOS; распространять нужно всю папку `artifacts/win-x64`:

```sh
dotnet publish src/WukongRunner.Cli -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -o artifacts/win-x64
```
